Concordia is a bounded data-integration agent for teams that must join records across fragmented sources. For each enrolled universe (SEC companies, NY taxi zones, MaDI companies, a GTFS transit subset and synthetic fixtures), it discovers tables through Zetaris, proposes candidate joins (rules plus COMA schema matching), picks bounded reads from a fixed catalog, probes relations with capped SQL, and an adversarial critic challenges what looks supported. The model never writes SQL or verdicts: deterministic rules decide. Sample impact: a misleading U1 join gave wrong zone labels to 20/20 sample catalog records; a literal CIK join lost the 1/1 U2 sample link. Governed memory runs on the Meterless H-MEM Engine: the upstream reference implementation, vendored with one added ledger-restore method, passes the public H-MEM conformance suite 13/13 against our build. Concordia's adapter adds the governance: only evidence-sustained relations with run-id provenance, separated by origin, in an append-only ledger; a live two-pass GTFS run reused one with 0 model generations. Nightshift is the only AI provider; every call is receipted and budget-bounded (the final live U2 run used 6,344 of its 50,000-token cap). NVIDIA: not used. Human approvals are recorded with approver, date and quote in an append-only ledger. Positioning, from published abstracts we did not replicate (we ran no external benchmark): Spider 2.0 and KramaBench report 21–55% for agents writing free-form SQL or pipelines on enterprise and lake tasks; Concordia avoids that error class by design. Agent-memory work such as Mem0 and A-MEM measures conversational recall; ours is evidence-governed. Governance receipts proposed in 2026 (AgentBound, an IETF draft) already run here. Findings are bounded-sample results, not global guarantees. Apache-2.0 code at v1.1-rc7: 1,205 tests (1,198 pass, 7 skipped), CI green; third-party data keep their own terms.
